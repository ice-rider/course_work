\# Техническое задание № 3 (Школа) — Обновленная версия



\## 1. Назначение системы

Разрабатываемая программная система предназначена для автоматизации работы завуча школы. Система должна обеспечивать ведение учета кадров (учителя), контингента (ученики, классы), учебной нагрузки (предметы, кабинеты) и успеваемости (оценки).



\## 2. Хранение сведений (Бизнес-сущности)

Система должна обеспечивать хранение и обработку следующих данных:



\### 2.1. Учителя

\*   \*\*Личные данные:\*\* Фамилия и имя учителя.

\*   \*\*Преподаваемые предметы:\*\* Возможность закрепления за одним учителем списка из нескольких предметов.

\*   \*\*Кабинет:\*\* Закрепление за учителем ровно одного кабинета (множественное закрепление не допускается).



\### 2.2. Ученики

\*   \*\*Личные данные:\*\* Фамилия и имя ученика.

\*   \*\*Класс:\*\* Принадлежность ученика к конкретному классу.

\*   \*\*Успеваемость:\*\* Оценки за текущую четверть по каждому предмету.



\### 2.3. Классы

\*   \*\*Наименование:\*\* Уникальное обозначение класса (например, «5Б», «10А»).

\*   \*\*Статус:\*\* Классы существуют как самостоятельные сущности, не зависящие от наличия в них учеников.



\### 2.4. Предметы

\*   \*\*Наименование:\*\* Название учебного предмета (например, «Алгебра», «Физика»).

\*   \*\*Статус:\*\* Список предметов не является фиксированным, формируется пользователем.



\### 2.5. Оценки

\*   \*\*Значение:\*\* Целочисленное значение в диапазоне от 2 до 5.

\*   \*\*Контекст:\*\* Оценка привязана к ученику, предмету и текущей четверти.



\## 3. Функциональные требования (Бизнес-логика)



\### 3.1. Управление справочниками

\*   \*\*Предметы:\*\* Завуч должен иметь возможность создавать, просматривать и вести список учебных предметов при первом и последующем пользовании системой.

\*   \*\*Классы:\*\* Завуч должен иметь возможность вручную создавать новые классы (например, при формировании параллели).



\### 3.2. Управление учителями

\*   \*\*Добавление:\*\* Возможность регистрации нового учителя в системе.

\*   \*\*Нагрузка:\*\* При регистрации или редактировании учителя должна быть возможность выбрать один или несколько предметов из справочника, которые он преподает.

\*   \*\*Кабинет:\*\* При регистрации или редактировании учителя должна быть возможность указать номер закрепленного кабинета (только один).



\### 3.3. Управление учениками

\*   \*\*Добавление:\*\* Возможность добавления нового ученика в систему.

\*   \*\*Распределение:\*\* При добавлении ученика должна быть предусмотрена удобная форма для выбора существующего класса и зачисления в него.

\*   \*\*Перевод:\*\* Возможность изменения класса у существующего ученика (редактирование поля «Класс») для перевода в следующий класс или параллельный класс. Удаление и повторное добавление для этого не требуется.



\### 3.4. Управление оценками

\*   \*\*Ввод оценок (Сценарий 1 — По классу):\*\* Возможность массового ввода оценок по принципу: Выбор класса -> Выбор предмета -> Ввод оценок списком для всех учеников данного класса.

\*   \*\*Ввод оценок (Сценарий 2 — По ученику):\*\* Возможность ввода всех оценок для конкретного ученика по принципу: Выбор ученика -> Ввод оценок по всем предметам.

\*   \*\*Валидация:\*\* Система должна принимать только оценки в диапазоне от 2 до 5.

\*   \*\*Неизменность:\*\* После сохранения выставленной оценки система должна запрещать её редактирование или изменение.



\## 4. Ограничения и правила

\*   Один учитель не может быть закреплен более чем за одним кабинетом.

\*   Один учитель может вести неограниченное количество предметов (из утвержденного списка).

\*   Редактирование ранее сохраненных оценок запрещено бизнес-процессом.

\*   Перевод ученика в другой класс осуществляется исключительно через редактирование карточки ученика.

\*   Список предметов изначально пуст и заполняется завучем.
